# 花漾生活 Design Skill

當需求涉及商品頁、購物袋、結帳、訂單確認或付款完成頁時，先套用此 Skill。目標不是只產生漂亮的單一畫面，而是把一套可延伸、可測試的花禮電商設計系統落到既有綠界金流流程中。

## 開始前先讀

1. `docs/design/README.md`：已核可的設計概念、產出工具與畫面對照。
2. `public/css/input.css`：目前可用的色彩 token、元件類別與互動規則。
3. 對應的 EJS 頁面與 Vue page script：不得為了視覺而破壞既有 API 或付款流程。

## 設計定位

- 品牌：花漾生活，精品但親切的台灣花禮店。
- 氛圍：安靜、細緻、有送禮的儀式感；避免制式後台感與過度可愛的貼圖風格。
- 主要色：Wine `#311923`、Rose `#9D4658`、Paper `#FFFDF9`、Cream `#F7F0E8`、Olive `#65745C`。
- 字體：標題使用 `Noto Serif TC`；操作與長文使用 `Noto Sans TC`。
- 付款語意：Olive 只用於安全付款、成功與安心狀態；失敗需使用清楚的紅色警示，不可偽裝成成功。

## 必須維持的資訊層級

1. 商品名稱、價格、庫存／可訂狀態。
2. 使用者下一步動作（加入購物袋、送出訂單、前往綠界）。
3. 訂單總額與配送資訊。
4. 綠界付款目前狀態與可追溯的訂單編號。

金流 CTA 必須讓使用者知道會離開本站前往綠界；不可把「建立訂單」與「付款完成」混為同一個狀態。

## 實作工作流程

1. **先定義畫面目的**：說明此頁處於瀏覽、結帳、待付款、付款成功或付款失敗哪一個階段。
2. **以 MCP 產出或調整設計概念**：使用可用的設計工具，產出的設計稿、截圖或原始設計檔必須存到 `docs/design/`。
3. **建立可重用的視覺規則**：優先擴充 `public/css/input.css` 的 token 與元件類別，而非在每頁散落 inline style。
4. **切版既有流程**：保留 Vue 綁定、API 呼叫、表單驗證、`data-testid` 與無障礙 label。
5. **響應式檢查**：至少檢查 390px 與 1440px。手機版要保留完整 CTA、價格、進度與狀態；不得只是把桌面版硬縮小。
6. **保存實作佐證**：完成後以瀏覽器截圖存入 `docs/design/`，更新 `docs/design/README.md` 的對照表。

## 元件規則

- 主要動作用 `.primary-button`；綠界付款用 `.ecpay-button`。
- 資訊容器用 `.soft-card`；重要成功訊息可用 `.soft-card-dark`。
- 輸入欄位必須使用可見 label 和 `.field-input`，錯誤狀態要同時提供文字，不可只變色。
- 結帳頁要維持步驟指示、訂單摘要、免運／運費與 SSL 安心提示。
- 狀態卡要使用可讀文字，如「待付款」「付款完成」「付款失敗」，不要只用 icon。

## 完成條件

- 設計產出在 `docs/design/`，並能從 README 說明設計工具與產出日期。
- 商品頁、購物袋、結帳頁、訂單確認／付款完成頁與設計方向一致。
- 390px 與 1440px 沒有水平捲動、截斷的主要 CTA 或重疊內容。
- `npm run css:build` 成功。
- 付款流程使用的 `data-testid` 沒有被移除；接著執行 `e2e-payment-test` Skill 驗證。

## 建議呼叫方式

```text
使用 flower-commerce-design，依 docs/design 的概念稿調整花漾生活的結帳頁，
保留既有綠界付款流程，並在桌面與手機尺寸各做一次視覺驗收。
```
